# Allure Test Reporting Setup Guide

## Overview
Your TestX project is now configured with Allure reporting. Allure provides beautiful and comprehensive test reports with detailed analytics.

## Files Created/Updated
- **allureConfig.json** - Allure configuration file
- **.runsettings** - Test runner configuration for Allure integration
- **CommonBaseTest.cs** - Updated with Allure NUnit attributes

## Running Tests with Allure Report Generation

### Step 1: Run Tests
Execute tests using the .runsettings file to automatically generate Allure results:

```bash
cd /Users/nguyenquanganh/Peo_Test
dotnet test TestX.sln --settings .runsettings
```

Alternatively, if you want to run specific test fixtures:
```bash
dotnet test TestX.sln --filter "TestFixtureName" --settings .runsettings
```

### Step 2: Generate HTML Report
After tests complete, generate the Allure HTML report:

```bash
# Install Allure CLI if not already installed (macOS)
brew install allure

# Generate the report
allure generate allure-results --clean -o allure-report
```

### Step 3: View Report
Open the generated report in your browser:

```bash
# Open the report
open allure-report/index.html

# Or serve it locally

allure open allure-report
```

## Optional: Add Allure Attributes to Tests

You can enhance your test reports by adding Allure attributes to your test classes:

```csharp
using Allure.NUnit.Attributes;

[TestFixture]
[AllureNUnit]
[AllureSuite("Production Module")]
[AllureSubSuite("Settings")]
public class ProductionSettingsTest
{
    [Test]
    [AllureName("Verify stock catalogue settings")]
    [AllureDescription("This test verifies that stock catalogue settings can be configured correctly")]
    [AllureTag("smoke")]
    [AllureOwner("QA Team")]
    public void TestStockCatalogueSettings()
    {
        // Your test code
    }
}
```

### Available Allure Attributes
- **[AllureNUnit]** - Enable Allure reporting for the class
- **[AllureSuite]** - Group tests by suite/module
- **[AllureSubSuite]** - Add sub-suite grouping
- **[AllureName]** - Custom display name for test
- **[AllureDescription]** - Detailed test description
- **[AllureTag]** - Tag tests (e.g., "smoke", "regression")
- **[AllureOwner]** - Assign test owner
- **[AllureSeverity]** - Set test severity (Blocker, Critical, Normal, Minor, Trivial)

## Troubleshooting

### Allure CLI not found
Make sure Allure is installed:
```bash
brew install allure
allure --version
```

### No results generated
- Verify tests are actually running: `dotnet test TestX.sln -v normal`
- Check that `allure-results/` folder exists after test run
- Ensure `.runsettings` file is in the project root

### Report is empty
- Run tests with the `--settings .runsettings` parameter
- Check that your test classes have the `[AllureNUnit]` attribute
- Run tests in verbose mode to see if Allure listeners are attached

## Directory Structure
After running tests, your project will have:
```
allure-results/          # Raw Allure results (generated by tests)
allure-report/           # HTML report (generated by Allure CLI)
TestResults/             # .NET test results
```

## CI/CD Integration
For CI/CD pipelines, add these steps:
```yaml
- Run tests: dotnet test TestX.sln --settings .runsettings
- Install Allure: brew install allure (or apt-get for Linux)
- Generate report: allure generate allure-results --clean -o allure-report
- Archive artifacts: allure-report/ folder
```
